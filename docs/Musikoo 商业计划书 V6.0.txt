## 1. 执行摘要

Musikoo 构建的是**音乐世界的“元数据基础设施”**。

现有的音乐平台（如 Spotify、网易云）提供的是完整的音频流，乐谱平台（如 MuseScore、IMSLP）提供的是复杂的静态文档。而对于全球数以亿计的视频创作者、播客主理人、音乐教育者和内容生产者来说，他们真正需要的是：**一个已经拆解好的、带有情绪标签的、版权清晰可商用的、能直接拖进时间线的经典乐句。**
**用户只需对着手机哼唱一段记忆中的旋律，Musikoo 即可精确定位到对应的那个乐句，并返回该乐句所属作品的完整信息——包括作曲家、时期、情绪标签、可商用音频和乐谱。**

我们独创的 **Eye（歌眼）/Heart（高潮华彩）** 分级特征模型、**多维情绪与场合标签系统**，以及**旋律轮廓-首调旋律-独立节奏三层检索引擎**，将非结构化的音乐作品转化为高精度的结构化“乐句元件”。每个元件都是一个或多个完整乐句组成的独立呼吸单元，标注着“悲伤的”“婚礼的”“史诗感的”等自然语言标签，以及一段独一无二的、可供哼唱匹配的“旋律指纹”。

Musikoo 的架构从设计之初就是**音乐类型无关的**。我们以版权绝对清晰的公版古典音乐作为完美的训练场和数据启动资产，逐步扩展至民歌、传统音乐，并最终通过与版权平台合作的方式，成为连接任何音乐片段与最终正版体验的“检索中间层”。

这不仅仅是更好的搜索，这是对音乐作品进行结构化理解的全新方式。

## 2. 我们解决的问题

### 2.1 内容创作者的“选曲炼狱”

一个视频创作者需要为婚礼视频的感人片段配乐时，需求通常是：“一段钢琴为主、有点悲伤但又有希望、大约30秒、像一个故事结尾的古典旋律”。在今天，他需要：
- 在音乐平台听完数小时的古典歌单
- 依靠个人感觉判断情绪和截取位置
- 手动裁剪音频，祈祷情绪在高潮处完美收尾
- 担忧他所用版本背后的复杂录音版权

**我们把这个过程缩短到30秒。**

### 2.2 普通听众的“古典漫游障碍”

“那个开头‘等等等等’的曲子叫什么？”“这首曲子最好听的是哪一段？”古典音乐因其长度和复杂的结构，对于普通听众来说缺乏有效的“记忆锚点”和“探索入口”。

### 2.3 音乐教育与AI领域的“结构化数据饥渴”

- **教育科技**：钢琴教学App需要按难度和技巧分类的“名曲高光”作为练习素材，目前全靠人工手剪，成本极高。
- **AI音乐生成**：模型（如 Suno、Udio）能生成旋律，但缺乏“人类觉得什么是好听的旋律结构”的审美反馈数据。我们的 Eye/Heart 标记，本质上是在为机器提供**人类听觉美学的结构化答案**。

## 3. 我们的解决方案：Musikoo 乐句引擎

### 3.1 核心理念：从“整首作品”到“乐句元件”

我们不是乐谱图书馆，也不是音频播放器。我们将每一部音乐作品处理成一个**结构化的乐句集合**，每一个乐句都是一个独立、可用、可检索的产品。

### 3.2 产品核心功能

| 功能模块 | 描述 | 用户价值 |
| :--- | :--- | :--- |
| **多维标签筛选器** | 情绪（悲伤、喜悦、庄严）× 场合（婚礼、睡前、专注）× 乐器 × 时长 × 乐曲位置（开头/高潮/结尾） | 像逛超市一样找音乐 |
| **乐句波形浏览器** | 每个片段配有波形图，清晰标注 Eye/Heart 位置，支持在线拖拽调整入点、出点 | 所见即所得，精准定位 |
| **Eye/Heart 精华导航** | 每首作品标注1-3个“歌眼”（最抓耳的段落）与“Heart”（情绪推向顶点的华彩），创作者可直接取用 | 跳过冗长探索，直达精华 |
| **分层下载与授权** | 低码率MP3免费使用（带平台水印），高品质WAV及分轨文件通过订阅获取，附带清晰的商用授权证书 | 版权安全，创作者无忧 |
| **🎤 哼唱搜索**| 用户对着设备哼唱、吹口哨或弹奏单音旋律；系统自动将其转换为帕森斯轮廓码和首调简谱向量，与数据库进行双层级匹配，**精确定位到具体的那个乐句**，而非仅仅返回“可能是哪首歌” |**记忆中的旋律终于有了名字和入口**。这是Shazam做不到的事——它识别正在播放的录音，而我们识别你脑海中的旋律 |

## 6. 技术概要

*（详细的算法、存储模型、检索架构请参见单独的《Musikoo 技术设计文档》。此处仅概述商业相关的技术逻辑。）*

### 6.1 乐句级结构化拆分

我们基于乐谱（MusicXML），结合音乐理论规则与深度学习模型，将作品切割至“完整乐句”颗粒度。初期由机器预切，再由音乐专业人员通过我们自建的Web工作台进行微调确认。这个过程建立了高质量的核心数据壁垒，并随着数据积累持续训练AI，提高自动化程度。

### 6.2 多层特征提取与标签体系

- **客观层**：拍号、调性、速度、主要乐器——由MusicXML自动提取，零误差。
- **功能层**：乐句在结构中的角色（前奏、主题、发展、高潮、尾声），以及 Eye/Heart 的特殊标记。Eye根据旋律的记忆点（重复性、新颖性、主题关联度）排序，Heart根据多维音乐参数的峰值得分定位。
- **主观层**：情绪（悲伤、欢乐、忧郁、庄严等）和场合（婚礼、睡前、专注、运动等）标签。采用“模型预标注+人工专家精标+用户数据回流校正”的闭环流程，确保标签的准确性。

### 6.3 模糊检索引擎

我们独创的三层检索架构解决了“用户表达模糊”和“音乐版本差异”两大难题：

| 检索层 | 技术实现 | 解决的问题 | 用户场景 |
| :--- | :--- | :--- | :--- |
| **旋律轮廓** | 帕森斯代码（Parsons Code） | 完全记不清音高和节奏，只记得旋律“形状” | “那个上上下下然后突然上去的调子” |
| **旋律身份指纹** | 首调唱名法简谱 | 同一旋律的不同调性版本、不同乐器演奏的精准匹配 | 听到一段旋律后哼唱搜寻 |
| **独立节奏向量** | 归一化时值序列 | 纯节奏搜索、跨旋律的节奏型匹配 | 敲击一段节奏找音乐 |

这三种方式可在检索时独立工作或动态加权融合，实现对各种模糊输入的极高容忍度和精准度。

### 6.4 版权安全与音频渲染

所有素材均源自公版乐谱。我们使用高品质虚拟乐器进行重新渲染合成，**完全避免使用任何受版权保护的原版录音**。我们为每个可供下载的片段生成清晰的授权证书，确保创作者在全球任何平台使用都无版权风险。

## 7. 市场进入策略

### 7.1 数据冷启动：公版古典音乐是完美的第一场景

- **版权清晰**：公版乐谱资源丰富（IMSLP、OpenScore等），音乐合成权利完全自有，从根源上解决可商用问题。
- **需求明确**：古典音乐是高级感视频背景音乐的最重要来源，长尾搜索量巨大。
- **结构规整**：古典音乐标准化的音乐结构，是训练和打磨我们结构化分析引擎的最佳训练场。

### 7.2 社区冷启动：KOL合作与众包标注

- **种子内容**：精选200首高频古典名曲（《卡农》《G弦上的咏叹调》《月光》《四季》等），进行高精度人工精标，打造无可挑剔的“标杆体验”。
- **KOL合作**：与10-20位视频创作、音乐教育领域的KOL合作，提供专属会员资格，换取使用反馈与内容推广。
- **众包生态**：邀请音乐学院师生、资深乐迷参与乐句边界微调、情绪标签校准，以积分、会员权益交换标注劳动。系统记录所有修正并回流进训练集，形成正向数据飞轮。

### 7.3 扩展路径：从古典到全音乐类型

1.  **Phase 1（古典聚焦）**：公版古典音乐，打磨核心流程，建立产品口碑。
2.  **Phase 2（无版权音乐扩展）**：纳入公有领域的世界民歌、传统音乐，验证模型对多样化音乐形式的适应性。
3.  **Phase 3（现代音乐索引层）**：与正版乐谱平台、版权音乐库建立合作。我们不做流行音乐的版权内容分发，而是成为其**“检索和发现中间层”**——用户在我们平台找到“某首流行歌副歌的某个情绪片段”，跳转至合作方获取正版授权。

## 10. 结语

Musikoo 做的事情，是在构建数字音乐时代缺失已久的一层基础结构。

我们不是另一个播放器，让用户被动收听。我们也不是另一个曲谱站，让用户茫然无措。我们做的是 **“音乐的索引层”**——它告诉创作者，那个最动人的片段在第几秒；它告诉AI，人类觉得怎样的旋律走向最动人心魄；它告诉每一个普通人，你脑海中的那段旋律，不是模糊的记忆，它可以有一个名字，有一个准确的入口。

在视频生产力爆发、AI生成内容泛滥的时代，**音乐的结构化理解与审美标引，将成为下一项稀缺的战略资源。**

我们诚邀您，一起构建这座属于全人类的“音乐基因库”。
